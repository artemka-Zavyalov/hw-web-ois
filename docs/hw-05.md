## Часть 1. Мои записи и отмена

Отмену записи перенёс на адрес:

`DELETE /api/events/{event_id}/registrations/me`

Запись не удаляется из `registrations`. У неё меняется `status` на `cancelled`.

Если пользователь не вошёл в систему, возвращается `401`. Если активной записи нет — `404`. Если мероприятие уже началось — `409`.

Также добавил:

`GET /api/me/registrations`

Он возвращает только активные записи текущего пользователя: id мероприятия, название, время начала и аудиторию. Записи сортируются по времени начала.

Для получения списка используется один SQL-запрос с JOIN, поэтому количество запросов не увеличивается вместе с количеством записей. Это можно проверить с помощью:

```powershell
$env:SQL_ECHO="1"
```

После запуска API запрос:

`GET /api/me/registrations`

В консоли должен быть виден один запрос на получение списка.

## Часть 2. Смена пароля

Добавил:

`POST /api/auth/password`

Тело запроса:

```json
{
  "old_password": "старый пароль",
  "new_password": "новый пароль длиной минимум 15 символов"
}
```

Если пользователь не вошёл, возвращается `401`. Если старый пароль неверный — `400`. Проверку минимальной длины нового пароля выполняет Pydantic, поэтому для пароля короче 15 символов возвращается `422`.

Новый пароль сохраняется не в открытом виде, а в виде Argon2-хеша.

После смены пароля удаляются все остальные сессии пользователя. Текущая сессия не удаляется, поэтому после смены пароля пользователь остаётся авторизован.

Удалять остальные сессии нужно для безопасности. Если пароль узнал другой человек или старая сессия осталась открытой на чужом устройстве, после смены пароля этой сессией нельзя будет продолжать пользоваться.

Проверка: войти одним пользователем в двух окнах, сменить пароль в первом окне и сделать запрос из второго. Во втором окне старая сессия должна получить `401`.

## Часть 3. Ограничение попыток входа

Добавил таблицу `login_attempts`. Попытки хранятся в базе данных, а не в памяти приложения.

Для одного email разрешено максимум 5 неудачных попыток за последние 15 минут. На шестой попытке возвращается:

`429 Too Many Requests`

с сообщением:

`Слишком много попыток, попробуйте через N минут`

Проверка ограничения выполняется до проверки пароля, поэтому шестая попытка получает `429` даже при правильном пароле.

Почему нельзя отвечать «пароль верный, но подождите»: это позволяет узнать, что пароль правильный. Для злоумышленника это фактически подсказка, что пароль угадан. Поэтому после превышения лимита система должна отвечать одинаково независимо от правильности введённого пароля.

Счётчик нельзя хранить только в памяти процесса, потому что API может работать в нескольких копиях. Один запрос попадёт в первый процесс, другой — во второй, и у каждого будет свой счётчик. В результате ограничение можно будет обойти. База данных общая для всех копий приложения, поэтому все они видят одни и те же попытки.

Успешный вход не удаляет старые неудачные попытки. Учитываются все неудачные попытки за последние 15 минут.

## Часть 4. Журнал действий в базе

Добавил таблицу `audit_log` через Alembic-миграцию. В ней хранятся:

- время действия;
- пользователь-администратор;
- действие;
- раздел (`identity`);
- id объекта;
- изменения в `jsonb`.

Для SQLAdmin сделал собственный класс `AuditDbBackend`, который наследуется от `AuditBackend` и записывает действия в `audit_log`. Вместо `LoggingAuditBackend` теперь используется он.

Обычные действия SQLAdmin (`create`, `update`, `delete`) записываются автоматически. Для действий «Опубликовать» и «Отклонить» запись в журнал добавляется отдельно.

В админке появился раздел «Журнал». Он только для просмотра: создание, редактирование и удаление отключены. По умолчанию записи сортируются по времени от новых к старым.

Для отклонения мероприятия теперь обязательно заполнить `reject_reason`. Если причина не указана, мероприятие остаётся в статусе `pending`, а в админке появляется сообщение об ошибке.

## Миграция

Из каталога `api`:

```powershell
python -m alembic upgrade head
```

Проверить текущую ревизию:

```powershell
python -m alembic current
```

Откат последней миграции:

```powershell
python -m alembic downgrade -1
```

Вернуть миграцию:

```powershell
python -m alembic upgrade head
```
